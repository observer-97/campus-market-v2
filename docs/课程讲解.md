# 课堂讲解与复现提纲

## 目标

以四类校园闲置商品分类为例，将业务表单、数据处理、传统文本模型、验证选择及网页推理连接成一个可运行项目。现已增加校区信息、站内私信、模拟订单及模拟托管结算；付款仅为课堂模拟，无真实资金。

## 现有素材与改造

原目录含 Android Java 工程、APK、截图、PPT、实训报告和演示录屏。四类商品来自原工程 arrays.xml，原流程包含登录、发布和收藏。未发现结构化标注数据；本项目保留原目录，独立补充 Django 网页和课程语料。没有把旧工程截图或 Android 数据当成新模型的实验结果。

## 数据流程

说明 examples.csv 六字段和 source。先清空字段、去完全重复，再在划分前合并人工同组与近重复连通组。展示 study-001 与 study-025 共用模板组，核查 split_manifest.csv 中相同 leakage_group 只能在一个集合。这样避免近似文本跨集合抬高指标。启发式仍会漏检语义改写，需要人工标记。

本次数据 97 条、96 个组；训练 58，验证 21，最终测试 18，固定随机种子。验证用于模型选择，测试用于选型后的最后评估，不能根据测试错误反复挑模型再把同一测试集当独立结果。

## 文本模型

输入是标题、空格和描述。中文 char TF-IDF 无需额外分词依赖。字符一元、二元、三元片段转换为稀疏特征，TF-IDF 词表和逆文档频率只从训练集学习。NB 通过条件概率组合特征；LR 学习线性分类边界。两个 Pipeline 各自在同一训练集合拟合、验证集合比较。

当前 Macro-F1 与 Accuracy 完全平局，按预设规则选 NB。没有依据测试集调参。生产模型仍只用训练集合拟合，便于对应已保存的实验结果。模型支持概率也不意味着校准可靠；本页面只展示建议类别。

## 评价结果的解释

Accuracy 是预测正确数量占比。Macro-F1 等权平均四类 F1，避免数量较多的类别掩盖弱类。分类报告还给出每类 precision、recall 和 support；混淆矩阵的行是真实类别，列是预测类别，顺序为 study、digital、sports、daily。

打开 artifacts/evaluation.md，讲解生活用品的错误：带“照明”的化妆镜被错分电子，折叠雨伞被错分体育。这里可以讨论否定表达和跨用途物品的困难，但不要根据这次测试反复修改模型，再宣称新的测试指标是无偏结果。

本次所有语料为编写示例，语言分布和真实用户差异明显，数量很少，因此真实应用的泛化能力未知。下一阶段应收集合规真实文本、制定边界标注规则、审查重复组并保留新的独立测试集合。

## 常见故障

- 无模型：独立执行 train_model，成功后重启服务；页面明确提示并允许手动选择。
- 没有商品：执行 init_demo 或发布；不要直接覆盖数据库。
- 重复初始化：保留已有密码与内容，新增缺少的演示条目。
- 上传失败：核对实际图片格式、5 MB 和像素上限；改名为 PNG 不会绕过解析。
- 新增 CSV：字段和类别必须正确，每类至少 5 个独立分组；数据太少命令明确失败。
- Python 3.14：当前电脑该环境失败，使用 run.ps1 选择已验证的 3.12。
