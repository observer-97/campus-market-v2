# 青禾集 · 校园二手商品智能交易平台

校园二手交易课程网页，Django + scikit-learn，支持电脑和手机。四分类及发布、收藏业务参考早期 Android 工程，运行此项目不依赖 Android Studio，也不需要原 Android 资料。

## GitHub + Vercel 云端配置（2026-11-06）

上传前请先阅读 [零终端部署指南](docs/VERCEL部署指南.md)。访问已部署的 HTTPS 地址即可，无需 Python 或终端。
- 本地继续使用 SQLite；Vercel 强制使用 `DATABASE_URL` 指定的 PostgreSQL，禁止临时 SQLite。
- 在 Vercel 导入本仓库，Framework 选 Django，Python 3.12，构建命令 `python build.py`。
- 在 Storage / Marketplace 创建并连接 PostgreSQL（如 Neon），只授予 Production 环境。
- 配置随机 `DJANGO_SECRET_KEY`、精确 `DJANGO_ALLOWED_HOSTS` 和 HTTPS `DJANGO_CSRF_TRUSTED_ORIGINS`。
- 演示初始化：`CAMPUS_INIT_DEMO=1`、私有 `CAMPUS_ADMIN_USERNAME` 和至少 16 字符的 `CAMPUS_ADMIN_PASSWORD`。
- 首次构建迁移数据库、校验本项目模型，并初始化 9 件明确标记的演示商品。重复构建不会覆盖已有密码、商品或审核；只自动通过本次新建的演示商品，用户提交仍需管理员审核。
- 云端图片写入 PostgreSQL，适合小型课程演示；图片最大 3 MB，不依赖可写磁盘。不自动搬运本机用户或照片；需要保留的本机数据应另行备份。
- 静态资源由 Vercel 原生 Django 支持执行 collectstatic 并由 CDN 提供，分类模型随源码部署，网页请求只加载模型。
- 默认拒绝 Preview 构建向数据库执行迁移；本作业请从 main 分支发布 Production，避免共用数据库受预览代码影响。
- 公开演示账号无管理员权限、请勿填真实隐私；余额全为模拟。管理员密码只设在 Vercel 环境变量，不上传 GitHub、不写入构建日志。

## 校区、私信与模拟托管交易

### 账号设置、搜索筛选与举报

个人中心点击“账号设置 / 修改密码”，或直接访问 `/account/settings/`。支持修改简介、校区、默认联系方式和个人主页公开开关。默认联系方式只为新商品预填，公开主页不展示，也不会修改已发布商品；发布页在联系方式旁再次提示其公开范围。修改密码在 `/account/password/`，必须验证旧密码并符合 Django 密码强度规则，成功后当前会话保留。

市场新增最低/最高价格（包含边界）、发布起止日期（按香港时区、包含结束日全天）、最新/最早发布、价格升降序。所有条件保存在 URL、控件回显和分页链接中，可复制链接分享同样的筛选。价格或日期格式非法、区间颠倒时显示错误，不忽略错误继续返回混乱结果。

首页默认只显示商品列表上方的关键词搜索条；点击右侧筛选图标展开分类、校区、价格、日期和排序。校区可选全部、明故宫、将军路或天目湖，按卖家账号当前设置筛选，与商品详情的校区一致；未设置校区的商品仅出现在全部校区中。校区条件会随搜索和分页保留，并显示在已应用条件摘要中。应用后收起面板，并用数量和简短标签提示已选条件。再次点击图标收起；错误条件会自动展开便于修改。面板使用浏览器原生折叠控件，可用键盘操作，不依赖 JavaScript。

登录用户在他人商品详情点击“举报违规商品”，选择类型并填写说明；在 `/reports/` 查看“我的举报”。同一用户对同一商品仅允许一条待处理举报，防止重复提交；不能举报自己的商品，也不能举报无权查看的待审商品。

管理员在 `/admin/` → “商品举报”中筛选待处理，查看说明后选择“已处理”或“不予受理”，必须填写处理结果，系统记录管理员与时间。举报人可查看结果，卖家和其他用户看不到举报人身份及说明。举报不自动下架商品，管理员核查后在商品后台另行处理；原商品即使被删除，举报标题及处理结果仍保留。

当前电脑已应用 0009 迁移。重启旧服务后生效；如浏览器 8001 仍显示旧路由，应先停止原终端服务再重新启动。最新测试与页面验收记录见 `docs/账号搜索举报验收.md`。

本功能已按用户选择采用课堂模拟：所有余额、付款、托管、退款、结算均为本地数据库记录，不涉及真实资金，没有支付 API、充值、提现或实际分账。

个人中心可选择明故宫校区、将军路校区、天目湖校区；公开主页和商品详情显示卖家校区。既有账号不会被猜测或强行指定校区，未填写时明确提示“尚未设置”，请先自行补充。个人中心不公开时，商品详情仍显示卖家填写的校区，保存设置前页面会提示这一点。

商品详情点击“私聊卖家 / 协商交易地点”，建立按商品和买家隔离的会话。私信仅买卖双方通过网页访问，支持持久化与历史翻页，不采用 WebSocket；点击“刷新消息”查看新内容。不要填写真实敏感资料进行课堂测试。

交易步骤：买家和卖家私聊商定 → 买家选择交易校区、填写具体地点并发起意愿 → 卖家核对金额和地点并确认 → 买家领取模拟余额并模拟付款 → 模拟余额从买家扣除，冻结在订单中 → 线下交付后买家勾选已收到商品、确认收货 → 模拟款项记入卖家余额，商品自动标记已售出。订单保存价格、标题、商品版本和交易地点快照，个人校区变更不会篡改历史约定。地点更改需取消并重新发起。

付款前任一方可取消。付款后买家可私聊要求退款，由卖家点击“取消交易并退还买家模拟款项”；退款返回买家模拟余额。未设置争议仲裁、自动超时、实际支付回调等真实支付能力，卖家不处理退款时只能保留待交付状态；本地课堂可用两账号演示退款。

同一商品只能有一笔被接受/已付款的交易；锁定期间不能修改商品或手动改交易状态。后台订单、余额、流水与交易事件只读，不能通过表单直接改账。金额以整数分存储，使用事务、条件更新与唯一约束控制重复付款及重复结算。余额可每账号领取一次 1000 元，既不能转账，也无真实价值。

顶部“个人中心”打开 `/center/`，自动定位当前用户的 `/users/用户ID/` 主页。每个用户都可填写简介，默认不公开，勾选“公开我的个人中心”并保存后，访客无需登录即可访问。商品列表和详情中的卖家名称链接到该主页。关闭公开后访客仅看到未公开提示。

本人可使用“调整交易状态”标记售出或下架，后端检查商品归属；重新上架进入待审核。编辑商品也重新进入待审核的拟在售状态，不绕过审核。非在售商品从市场和搜索移除，但保留在公开主页对应分类中；非在售详情不再向访客显示联系信息。

前台原“删除商品”现为“下架我的商品”，不删除数据及历史。商品卡片展开“商品历史记录”，查看提交、审核、交易状态的时间和标题快照；私有审核历史只给本人显示，访客仅查看审核通过的历史快照。后台出于违规处理仍可永久删除商品及关联历史，并非不可删除的审计存档。

升级先执行 `.\run.ps1 migrate`，当前电脑已完成。已有商品建立升级时的当前状态基线，不补造以往历史。卖家可手动标记售出，也可由模拟订单确认收货后自动标记；两者都不代表经过真实支付验证的成交。验证记录见 `docs/个人中心验收.md`。

在“我的发布”或自己的商品详情点击“编辑商品”，可修改价格、描述、图片、联系方式，也可修正标题和类别。未选择新图片时保留原图，选择清除可移除原图。编辑接口按当前登录用户和商品归属查询，其他用户访问或提交返回 404；不能在表单中伪造卖家或审核状态。

新商品默认“待审核”。后台 `/admin/` → 商品 → 按上架状态筛选待审核 → 点击每行的“审核”按钮（也可点击商品标题），查看内容后将上架状态选为“已上架”（通过）或“已驳回”，保存。驳回必须填写理由。后台记录审核人和时间；卖家在我的发布和详情中查看状态与驳回理由。后台商品编辑页保留版本校验，若卖家已重新提交，旧审核表单必须刷新后再审核。

卖家保存任何修改后，商品重新待审核，原审核结果和理由清空，审核通过前停止公开展示。未通过商品不出现在市场、搜索或其他用户收藏列表，其他用户直接访问详情也会返回 404；收藏关系仍保留，通过后可再次显示。后台管理入口独立，不通过前台详情访问未审核商品。

## 功能与设计

### 图形化管理后台

访问 `/admin/`，或点击网页顶部“管理后台”。使用独立管理员账号登录；普通注册用户没有后台访问权限。已在当前数据库创建 `campus_admin`，初始随机密码在创建时输出，不保存为明文文件。新环境执行 `.\run.ps1 init_admin` 创建管理员并获取随机密码；同名普通账号不会自动获得管理员权限，已有管理员密码也不会被重置。忘记密码可执行 `.\run.ps1 changepassword campus_admin` 交互重置。

- 商品：查看、搜索、按分类/日期筛选，新增、修改价格/描述/卖家/联系信息/图片，删除违规商品（支持批量操作和删除确认）。更改直接反映到网页。后台图片上传复用前台格式和大小校验。
- 收藏记录：查询、新增、修改、删除用户收藏。删除商品会级联清除相关收藏。
- 用户与组：管理账号、停用账号、重置密码、配置后台工作人员和分组权限。超级管理员拥有全部权限；普通工作人员必须显式分配对应模型的查看/新增/修改/删除权限。
- 管理员变更记录：商品、收藏及用户编辑页提供历史记录；后台会记录管理员的新增、修改和删除操作。

普通用户在前台仍只能删除自己的商品。管理员管理全站数据通过独立的后台权限执行；不向前台普通账号开放全站操作。

- Django 自带 UserCreationForm、LoginView、LogoutView 和密码哈希、登录会话。
- 商品发布、详情、关键词与分类组合筛选、分页、我的发布、删除自己的商品。
- 收藏、取消收藏、我的收藏；数据库约束防止重复收藏。
- 后端登录与归属校验；修改均为 POST 并开启 CSRF。模板自动转义用户文本。
- 标题最多 100 字，描述最多 3000 字，价格大于零，联系信息必填。图片实际解析 JPEG/PNG/WebP，最多 3 MB、2000 万像素；上传名改为 UUID。
- 无商品、无搜索结果、输入为空、模型缺失/损坏、无可识别特征均明确提示。预测失败仍可手选。
- 页面使用本地 CSS，不依赖外部字体、CDN 或大模型接口。小屏导航换行、商品两列、发布和详情单列。
- 未实现可选的相似推荐，控制范围集中于交易与分类。

## 训练、评估与预测

```powershell
.\run.ps1 train_model
# 替换数据：
.\run.ps1 train_model --data D:\path\labeled.csv
# 重训后停止并重启服务，使内存中的模型更新
```

网页请求只加载本项目 `artifacts/category_model.joblib`，校验 `model_meta.json` 中的 SHA-256；缺少模型返回 503，不在请求中训练。joblib 是可执行的序列化格式，摘要只能帮助发现损坏，不能证明不可信文件安全；只使用本地训练命令生成的产物，不替换为外部模型或元数据。

97 条 AI 辅助编写示例，四类分别 25/24/24/24。清理和合并近重复组后，固定种子 20261022，用分层分组五折划分为训练 58、验证 21、测试 18 条，同组不跨集合。类别比例尽量保持，但小样本和分组约束使其不完全相同。TF-IDF 仅拟合训练集，字符 n-gram=(1,3)，sublinear_tf=True；两种分类器分别为 NB(alpha=0.5) 和 LR(C=4,max_iter=1500)。没有调参搜索。

仅用验证 Macro-F1（再比较 Accuracy）选型，平局默认 NB；选定之后输出两者最终测试结果。部署模型保留训练集拟合状态，不用验证或测试集重新训练。当前两算法验证和测试预测相同，不代表算法总体性能相同。
